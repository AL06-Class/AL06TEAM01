# 가치이음 웹앱 가치이웃 디자인 문서

## 문서 목적

이 문서는 Figma 파일 `가치이음 웹앱 가치이웃`에 설계된 화면을 기준으로, 가치이웃 즉 보호자와 도움 받는 당사자 관점의 모바일 웹앱 디자인 기준을 정리합니다.

개발 시 화면 구조, 정보 우선순위, UX 라이팅, 컴포넌트 톤을 맞추기 위한 기준 문서로 사용합니다.

## 기본 방향

### 핵심 경험

가치이웃 화면의 핵심은 빠른 매칭보다 신뢰할 수 있는 연결을 만드는 것입니다.

사용자는 낯선 가치제공자를 고르는 것이 아니라, 부모님이나 도움 받는 분을 안심하고 맡길 수 있는 사람을 확인하고 선택해야 합니다.

### 디자인 원칙

- 정보는 한 번에 이해하기 쉽게 카드 단위로 나눠요.
- 중요한 행동 버튼은 화면 하단이나 카드 하단에 명확하게 배치해요.
- 신뢰 정보는 숨기지 않고 프로필, 검색 카드, 요청 확인 화면에서 반복해서 보여줘요.
- 40대 이상 보호자가 읽기 편하도록 글자는 작게 쓰지 않아요.
- 요청 전, 요청 중, 요청 후 상태를 명확히 나눠 사용자가 지금 어느 단계인지 알 수 있게 해요.
- 불안한 대기 상태에는 진행 단계와 안심 문구를 함께 제공해요.

## UX 라이팅 기준

모든 사용자-facing 문구는 `~요`체를 기본으로 합니다.

### 문체 기준

- 딱딱한 행정 문구보다 부드럽고 짧은 문장을 사용해요.
- 사용자가 해야 할 행동을 명확하게 말해요.
- 불안한 순간에는 현재 상태와 다음 단계를 같이 알려줘요.
- 과한 친근함보다 차분한 신뢰감을 우선해요.

### 문구 예시

| 상황 | 권장 문구 |
|---|---|
| 도움 요청 시작 | 어떤 도움이 필요하신가요? |
| 요청 작성 안내 | 필요한 도움과 방문 시간을 알려주시면 조건에 맞는 가치이웃을 찾아드릴게요. |
| 요청 확인 | 마지막으로 확인해주세요. |
| 요청 전송 | 선택하신 이웃님께 도움 요청을 보낼까요? |
| 매칭 대기 | 가치이웃의 응답을 기다리고 있어요. |
| 안심 안내 | 수락 전에는 결제가 확정되지 않아요. |
| 계획 확인 | 수행 계획을 확인했어요. 일정에 맞춰 서비스가 진행돼요. |
| 후기 유도 | 이용 경험을 짧게 남겨주세요. 다른 보호자에게 도움이 돼요. |

## 공통 디자인 시스템

### 색상

- 메인 컬러: `#A1CCA5`
- 강조 딥그린: `#003434`, `#004D4D`
- 보조 그린: `#416652`, `#709775`
- 배경: `#FBF9F6`, `#FFFFFF`
- 보조 배경: `#F5F3F0`, `#EEF6EF`
- 본문 텍스트: `#1B1C1A`, `#20231F`
- 보조 텍스트: `#3F4848`, `#5D6860`

### 레이아웃

- 모바일 기준 너비는 `390px` 프레임을 기준으로 해요.
- 좌우 기본 여백은 `20px`을 사용해요.
- 카드 간 간격은 `16px~24px` 범위로 유지해요.
- 하단 주요 CTA는 고정 버튼 형태를 우선 사용해요.
- 하단 네비게이션은 `홈`, `검색`, `매칭현황`, `내 정보` 4개 탭을 유지해요.

### 컴포넌트

- 카드: 독립된 정보 묶음에 사용해요.
- 배지: 인증, 상태, 영상 보유, 완료/취소 같은 짧은 상태를 표시해요.
- CTA 버튼: 주요 행동은 딥그린 배경, 보조 행동은 흰색 또는 연한 배경을 사용해요.
- 프로필 이미지: 원형 이미지를 기본으로 하고 인증 마크는 이미지 오른쪽 하단에 배치해요.
- 선택 칩: 도움 유형, 태그, 정렬 옵션에 사용해요.
- 진행 단계: 요청 접수, 확인 중, 매칭 대기처럼 상태 흐름을 보여줄 때 사용해요.

```text
가치이음 가치이웃 웹앱

1. 홈
   - 예정된 도움 요약
   - 매칭된 가치제공자 요약
   - 새로운 도움 요청하기
   - 최근 만난 가치이웃

2. 검색
   - 가치제공자 검색/탐색
   - 정렬
      - 거리순
      - 평점순
      - 낮은 가격순
   - 가치제공자 카드
   - 가치제공자 상세

3. 도움 요청
   - 도움 요청 작성
   - 요청 확인 및 보내기
   - 요청 접수/매칭 대기

4. 매칭현황
   - 진행 중
   - 일정 상세
   - 수행 계획 확인
   - 완료/취소 이력
   - 다시 요청

5. 채팅
   - 일정 조율
   - 요청사항 전달
   - 진행 상태 알림

6. 완료/결제/후기
   - 완료 확인
   - 결제
   - 후기 작성

7. 내 정보
   - 프로필 수정
   - 부모님 정보 등록/관리
   - 결제 수단 관리
   - 알림 설정
   - 글자 크기 설정
   - 고객지원
```

## 화면별 설계

### 1. 보호자 홈

Figma 기준 프레임: `2.수정보호자홈`

#### 화면 목적

보호자가 앱에 들어왔을 때 오늘 예정된 도움과 새로운 요청 시작점을 빠르게 확인하는 화면입니다.

#### 주요 구성

- 상단 바
  - 로고
  - 역할 선택: `보호자`
  - 알림 아이콘
- 예정 도움 카드
  - `D-1 내일 예정`
  - 요청 수락 완료 상태
  - 일정 요약
  - 가치제공자 요약
  - `상세정보 보기`
  - `채팅하기`
- 새로운 도움 요청 카드
  - 일러스트
  - 도움 요청 설명
  - `도움 요청하기`
- 최근 만난 가치이웃
  - 최근 이용한 가치제공자
  - `다시 요청`

#### UX 라이팅

- `내일 오후 2시 장보기 동행이 예정되어 있어요.`
- `가치이웃에게 도움을 요청해보세요.`
- `장보기, 말벗 등 다양한 도움을 간편하게 요청할 수 있어요.`
- `다시 요청할 수 있어요.`

#### 설계 기준

- 홈은 사용자가 현재 진행 중인 도움을 먼저 확인하게 해요.
- 새 요청 CTA는 일정 카드 아래에 배치해 자연스럽게 다음 행동으로 이어지게 해요.
- 최근 만난 가치이웃은 재요청 전환을 위한 보조 영역으로 사용해요.

### 2. 가치제공자 검색

Figma 기준 프레임: `청년 가치 제공자 찾기 (검색)`

#### 화면 목적

보호자가 신뢰 정보를 비교한 뒤 직접 가치제공자를 선택할 수 있게 하는 화면입니다.

#### 주요 구성

- 상단 카피
  - 서비스 가치 설명
  - 탐색 시작 문구
- 정렬 칩
  - 거리순
  - 평점순
  - 낮은 가격순
- 가치제공자 카드
  - 프로필 사진
  - 영상 보유 배지
  - 이름
  - 시간당 금액
  - 평점/후기 수
  - 거리/지역
  - 가능 도움 태그
  - 소개 문구
- 하단 네비게이션

#### UX 라이팅

- `사람의 시간과 경험, 따뜻한 마음을 연결해드려요.`
- `도움이 필요한 사람과 도움을 나누는 사람을 연결해드려요.`
- `거리순`
- `평점순`
- `낮은 가격순`
- `영상보유`

#### 설계 기준

- 검색 화면은 도움 신청 화면과 분리해요.
- 검색 화면에서는 비교와 탐색이 목적이므로 정렬 옵션을 유지해요.
- 가치제공자 카드에는 가격보다 신뢰 정보, 후기, 가능 도움을 함께 보여줘요.

### 3. 가치제공자 상세

Figma 기준 프레임: `청년 가치 제공자 프로필 (인증 마크 추가)`

#### 화면 목적

보호자가 요청 전 가치제공자를 신뢰할 수 있는지 판단하게 하는 상세 화면입니다.

#### 주요 구성

- 프로필 히어로
  - 원형 프로필 사진
  - 인증 마크
  - 이름
  - 거주 지역/경력
  - 가능 도움 태그
- 신뢰 인증 배지
  - 본인인증
  - 신원인증
  - 범죄경력
  - 응급처치
  - 지역인증
- 핵심 지표
  - 매칭 완료
  - 재매칭 비율
  - 평균 별점
  - 응답 속도
- 자기소개 영상
- 도움을 드리는 이유
- 주요 서비스 이력
- 이용자 후기
- 하단 CTA
  - 채팅하기
  - 도움 요청하기

#### UX 라이팅

- `영상으로 신뢰를 확인해보세요.`
- `도움을 드리는 이유`
- `주요 서비스 이력`
- `이용자 후기를 확인해보세요.`
- `도움 요청하기`

#### 설계 기준

- 상세 화면은 스펙 나열보다 신뢰 판단에 필요한 정보 순서로 구성해요.
- 자기소개 영상은 텍스트보다 먼저 신뢰를 형성하는 핵심 요소로 보여줘요.
- 후기와 서비스 이력은 보호자의 선택 확신을 높이는 영역으로 사용해요.

### 4. 도움 요청 작성

Figma 기준 프레임: `도움 요청하기 (작성)`

#### 화면 목적

보호자가 필요한 도움, 방문 시간, 장소, 요청 내용을 부담 없이 작성하게 하는 화면입니다.

#### 주요 구성

- 상단
  - 뒤로가기
  - 제목: 도움 요청하기
- 안내 카피
  - 도움 요청 목적 설명
- 도움 유형 선택
  - 장보기
  - 병원 동행
  - 말벗
  - 디지털 기기 교육
  - 짐 옮기기
  - 기타
- 방문 날짜/시간
- 방문 지역/상세 주소
- 요청 메모
- 안심 안내 카드
- 하단 CTA

#### UX 라이팅

- `이웃에게 도움을 요청해보세요.`
- `믿을 수 있는 가치이웃들이 기다리고 있어요.`
- `어떤 도움이 필요하신가요?`
- `언제 방문할까요?`
- `어디로 방문할까요?`
- `도움이 필요한 내용을 자세히 적어주시면 더 적합한 이웃을 추천해드릴 수 있어요.`
- `모든 가치이웃은 본인 인증 및 범죄 경력 조회가 완료된 신뢰할 수 있는 분들이에요.`

#### 설계 기준

- 이 화면에서는 상세검색 필터를 제거해요.
- 사용자는 사람을 찾는 것이 아니라 도움 요청을 작성하는 중이라고 이해해야 해요.
- 입력 영역은 도움 유형, 일정, 장소, 요청 메모 순서로 구성해요.
- 하단 버튼 문구는 `조건에 맞는 가치이웃 찾기`보다 `요청 내용 확인하기`가 더 명확해요.

### 5. 요청 확인 및 보내기

Figma 기준 프레임: `요청 확인 및 보내기`

#### 화면 목적

보호자가 요청 전송 전 핵심 정보를 마지막으로 확인하고 안심한 상태로 요청을 보내게 하는 화면입니다.

#### 주요 구성

- 상단
  - 뒤로가기
  - 제목: 요청 확인
- 안내
  - 마지막 확인 문구
- 도움 상세 정보
  - 도움 종류
  - 날짜 및 시간
  - 장소
  - 매칭된 이웃
- 예상 비용
- 안심 보호 안내
- 하단 CTA

#### UX 라이팅

- `마지막으로 확인해주세요.`
- `선택하신 이웃님께 도움 요청을 보낼까요?`
- `정확한 비용은 서비스 완료 후 확정돼요.`
- `가치이음은 모든 이웃의 신원을 검증해요.`
- `서비스 중 발생하는 모든 활동은 안심 보호 시스템의 보호를 받아요.`
- `요청 보내기`

#### 설계 기준

- 요청 전송 전에 금액과 장소를 눈에 잘 띄게 보여줘요.
- 불안 요소인 신원 검증, 비용 확정 시점, 보호 시스템을 명확히 안내해요.
- CTA는 한 개만 강조해요.

### 6. 매칭현황 진행 중

Figma 기준 프레임: `매칭현황 가치이웃`

#### 화면 목적

현재 진행 중인 요청과 매칭된 가치제공자를 확인하고 채팅 또는 일정 상세로 이동하게 하는 화면입니다.

#### 주요 구성

- 상단
  - 제목: 매칭현황
- 탭
  - 진행 중
  - 완료/취소
- 현재 진행 중인 요청 카드
  - 요청 상태
  - 요청 번호
  - 일정/도움 유형
  - 주소
  - 가치제공자 요약
  - 채팅하기
  - 일정 상세
- 과거 매칭 이력
- 전체 이력 보기

#### UX 라이팅

- `현재 진행 중인 요청`
- `요청 수락 완료`
- `채팅하기`
- `일정 상세`
- `과거 매칭 이력`
- `전체 이력 보기`

#### 설계 기준

- 진행 중 화면은 현재 요청 1개를 가장 강조해요.
- 채팅과 일정 상세는 같은 수준의 주요 행동으로 배치해요.
- 과거 이력은 진행 중 요청보다 시각적 우선순위를 낮춰요.

### 7. 완료/취소 이력

Figma 기준 프레임: `Html → Body`

#### 화면 목적

완료되거나 취소된 요청을 확인하고 후기 보기 또는 다시 요청으로 이어지게 하는 화면입니다.

#### 주요 구성

- 탭
  - 완료/취소
- 완료 카드
  - 완료 상태
  - 날짜/시간
  - 도움 유형
  - 파트너
  - 지역
  - 결제 금액
  - 후기 보기
- 취소 카드
  - 취소 상태
  - 날짜/시간
  - 도움 유형
  - 파트너
  - 지역
  - 금액
  - 다시 요청

#### UX 라이팅

- `완료`
- `취소됨`
- `후기 보기`
- `다시 요청`
- `이용 내역을 확인해보세요.`

#### 설계 기준

- 완료와 취소 상태를 배지 색상과 문구로 명확히 구분해요.
- 완료 건은 후기와 결제 내역으로 이어지게 해요.
- 취소 건은 다시 요청을 더 쉽게 시작하게 해요.

### 8. 보호자 수행 계획 확인

Figma 기준 프레임: `보호자 계획 확인`

#### 화면 목적

매칭된 가치제공자가 작성한 수행 계획을 보호자가 읽고 안심할 수 있게 하는 화면입니다.

#### 주요 구성

- 상단
  - 뒤로가기
  - 제목: 가치제공자 수행 계획
- 파트너 프로필 요약
  - 프로필 사진
  - 인증 상태
  - 재매칭률
- 예상 소요 시간
- 수행 단계
  - 방문 전 연락
  - 도착 및 상태 확인
  - 병원 동행 및 약국
  - 안전 귀가 및 보고
- 준비물
- 파트너 한마디
- 확인 완료 영역
- CTA
  - 확인 완료
  - 파트너에게 연락하기

#### UX 라이팅

- `가치제공자 수행 계획`
- `파트너님의 도움 수행 계획을 확인해보세요.`
- `예상 소요 시간`
- `수행 단계`
- `도착 15분 전 미리 연락드려요.`
- `보호자님 걱정 마세요. 안전하게 잘 모시고 오겠습니다.`
- `수행 계획을 확인했어요. 일정에 맞춰 서비스가 진행돼요.`
- `파트너에게 연락하기`

#### 설계 기준

- 보호자는 이 화면에서 수정하지 않고 읽기만 해요.
- 수행 단계는 숫자와 세로 흐름으로 보여줘요.
- 파트너 한마디는 정서적 안심을 주는 영역으로 사용해요.
- 확인 완료 버튼은 계획을 읽었다는 상태 확인 용도로 사용해요.

## 누락 보강 화면 제안

Figma에 이미 구현된 흐름 외에 MVP 완성도를 위해 아래 화면을 추가 설계하면 좋아요.

### 1. 매칭 성사 전 대기

- 요청 접수 완료
- 가치이웃 확인 중
- 매칭 확정 대기
- 요청 수정하기
- 요청 취소하기

권장 문구:

- `가치이웃의 응답을 기다리고 있어요.`
- `요청 내용을 확인한 가치이웃이 수락하면 매칭이 확정돼요.`
- `수락 전에는 결제가 확정되지 않아요.`

### 2. 완료 확인

- 가치제공자 완료 요청 확인
- 완료 내용 요약
- 완료 승인
- 문제 제기

권장 문구:

- `도움이 잘 완료되었는지 확인해주세요.`
- `완료 승인 후 결제가 확정돼요.`
- `문제가 있다면 알려주세요.`

### 3. 결제

- 최종 금액 확인
- 결제 수단 선택
- 결제 완료

권장 문구:

- `최종 금액을 확인해주세요.`
- `등록된 카드로 결제할게요.`
- `결제가 완료되었어요.`

### 4. 후기 작성

- 별점
- 좋았던 점 태그
- 후기 입력
- 공개 여부

권장 문구:

- `이용 경험을 남겨주세요.`
- `짧은 후기만으로도 다른 보호자에게 도움이 돼요.`
- `후기가 등록되었어요.`
